# Постановки трёх выбранных инициатив

Разделы 1–2 паспортов вынесены в Task1 для проверки задания 1. [Общий триаж и канвас, разделы 0–1](triage.md); подробные разделы 2–5 с качеством, данными и экспериментами находятся в [Task2/passports.md](../Task2/passports.md). Это согласованное представление тех же решений, а не новые инициативы или результаты испытаний.

## №1. Приоритизация ручной проверки операций

| Поле | Постановка |
|---|---|
| Без слова AI | Из истории операций и контекста формировать упорядоченную очередь для сотрудника финансового мониторинга |
| Какое действие изменится | Меняется порядок необязательной части ручных проверок при ограниченной ёмкости; обязательные проверки выполняются независимо от score |
| Объект и единица решения | Одна операция с контекстом клиента/контрагента и историческими окнами на cutoff; клиентские связи — контекст, не отдельное обвинение |
| Момент | Ежедневный batch до начала работы очереди; платежи не ждут синхронного ответа модели |
| Операция × модальность | Порядок/аномалия × таблица и время; назначение платежа пока даёт детерминированные признаки, без генерации текста |
| Где нужна обучаемая закономерность | IsolationForest оценивает необычность сочетания признаков, которую неудобно полностью описать пороговыми правилами; полезность этого ранжирования надо доказать |
| Выход модели | Непрокалиброванный anomaly score, modelVersion и диагностические признаки. Score не является вероятностью схемы |
| Бизнес-выход | Проверенная карточка READY/ABSTAIN/FALLBACK с источниками и причинами; сотрудник разбирает её в действующем процессе. Команд HOLD/RELEASE в модельном контракте нет |
| Источник правильного ответа | Экспертное суждение «требует дополнительного расследования по инструкции», слепая контрольная выборка, двойная разметка/арбитр. Эскалация, исход расследования и формальное подтверждение хранятся раздельно; последнее появляется с задержкой в месяцы |
| Конвейер | Source snapshot → as-of признаки (код) → anomaly scoring (ML) → schema/source/freshness/quota validation (код) → обязательная/контрольная/модельная очередь → человек → аудит исходов |
| Альтернативы и вопрос | Бизнес хочет приоритет проверки или квалификацию «схема/не схема»? Выбрана первая задача: подтверждённого эталона схем нет. Weak-label классификатор может воспроизводить существующие правила, baseline — текущий порядок |
| Чего не хватает | Прав обработки, инструкции/независимого gold, точного объёма обязательных дел M и доступной экспертной ёмкости; смещение старых проверок нельзя игнорировать |
| Вердикт | Гибрид; разрыв данных с планом закрытия. Ограниченный пилот допустим только после gates, промышленный классификатор схем не обоснован |

Рабочая модель ёмкости: `K_model = max(0, 10 000 − M − 1 000)` в месяц, где 1 000 — постоянный независимый контроль. Это проектное распределение общей ёмкости кейса, не дополнительные бесплатные проверки. [Качество/данные/эксперимент P1](../Task2/passports.md#p1-1-приоритизация-подозрительных-операций), [ADR-001](../Task2/ADR-001.md).

## №2. Оцифровка кредитных документов

| Поле | Постановка |
|---|---|
| Без слова AI | Превратить разрешённый скан или фото страницы кредитного документа в текст с координатами, который можно проверить и исправить |
| Какое действие изменится | Оператор исправляет распознанный текст вместо полной перепечатки; критичные реквизиты подтверждаются до использования |
| Объект и единица решения | Одна страница конкретной версии документа; исходный hash, page и bbox сохраняются |
| Момент | Асинхронно после загрузки; UI получает jobId и показывает статус, а не ждёт бесконечный синхронный запрос |
| Операция × модальность | Извлечение × документ/изображение |
| Где нужна обучаемая закономерность | OCR распознаёт символы и структуру строк на неоднородных сканах/фото. Антивирус, лимиты, deskew, типы и версионность выполняет обычный код |
| Выход модели | Текст, строки, координаты, confidence и версия движка; confidence требует калибровки на банковском корпусе |
| Бизнес-выход | Подтверждённая оцифрованная версия документа для андеррайтера и следующего этапа извлечения. OCR не изменяет реквизиты в кредитной системе самостоятельно |
| Источник правильного ответа | Ручная транскрипция разрешённых страниц с координатами; критичные числа проверяются двумя операторами с арбитражем расхождений |
| Конвейер | Document registry → quarantine/sandbox → preprocessing (код) → OCR (ML) → schema/source/quality validation (код) → ручное исправление → versioned verified spans |
| Альтернативы и вопрос | Нужен только поиск по тексту или автоматический перенос реквизитов? Для поиска требования мягче; перенос показателей — отдельная инициатива №18. Ручной ввод остаётся baseline/fallback |
| Чего не хватает | Распределения языков/форм/качества, числа страниц, разрешённого gold и подтверждённых прав. Нельзя оценивать только чистые сканы |
| Вердикт | Гибрид, с разрывом и планом: 600 страниц, сравнение Tesseract5 и допущенного кириллического PaddleOCR, контроль критичных полей человеком |

[Качество/данные/эксперимент P2](../Task2/passports.md#p2-2-ocr-кредитных-документов), [ADR-002](../Task2/ADR-002.md). Модель №2 выдаёт текст/координаты; единицы, периоды и экономический смысл показателя относятся к №18.

## №18. Извлечение финансовых показателей

| Поле | Постановка |
|---|---|
| Без слова AI | Из текста/таблиц документа получить кандидаты финансовых показателей с источником, периодом, валютой и единицей для проверки андеррайтером |
| Какое действие изменится | Уменьшается ручной перенос показателей в карточку; каждое критичное значение подтверждает человек. Кредитное решение в сервис не входит |
| Объект и единица решения | Один показатель версии документа за определённый период; ключ включает documentVersion, indicator, period и sourceSpan |
| Момент | Асинхронно после verified OCR или получения цифрового документа; результат доступен по запросу пакета |
| Операция × модальность | Извлечение и связывание × документ/текст/таблица |
| Где нужна обучаемая закономерность | Extractor ищет span/тип показателя в нестандартных формах; правила покрывают известные формы, resolver связывает период/единицу и типизирует decimal |
| Выход модели | Кандидат span и тип показателя, версия/оценка; не окончательное финансовое значение без проверки контекста |
| Бизнес-выход | Подтверждённая карточка показателей со ссылками на исходные строки. Missing → null/MISSING; конфликт → REVIEW, без выдуманного значения |
| Источник правильного ответа | Экспертно подтверждённый кортеж (значение, знак, единица, валюта, период, источник), включая отсутствующие и неоднозначные поля |
| Конвейер | Verified OCR/цифровой файл → context/spans → правила или XLM-R с дообученным token head → deterministic resolver/validator → андеррайтер → signed approved card |
| Альтернативы и вопрос | Нужны показатели из неструктурированных форм или расчёт коэффициентов из готовых полей? Второе решается программой. Для пилота выбран закрытый список: выручка, чистая прибыль, активы, обязательства, денежный поток; остальное → REVIEW |
| Чего не хватает | Утверждённого словаря/форматов, 400 разрешённых пакетов с gold, весов token head и замеров на новых формах. Base XLM-R сам не является готовым extractor |
| Вердикт | Гибрид; разрыв с планом закрытия. Не подтверждает истинность отчётности и не обнаруживает подделку автоматически; это отдельная постановка №10 |

[Качество/данные/эксперимент P3](../Task2/passports.md#p3-18-извлечение-финансовых-показателей), [ADR-003](../Task2/ADR-003.md). Извлечённые значения не принимаются автоматически на основании model confidence.
