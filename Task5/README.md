# Task5. Дополнительно: селлеры маркетплейсов

Это необязательная проработка будущего сценария, не фактически наблюдённая деградация RetailBank. Через3 месяца поступил новый сегмент: законный транзит/частые выплаты может выглядеть аномально.

| Гипотеза | Дешёвая различающая проверка | Действие |
|---|---|---|
| Изменился нормальный профиль, модель не знает сегмент | Слепая разметка100 селлеров и100 сопоставимых старых клиентов, одинаковые окна, доля ABSTAIN/precision@residualK | Новые сегментные признаки/репрезентативный fit sample, shadow challenger; не объявлять селлеров чистыми по категории |
| Сломался feed/признаки | Manifest, nulls, watermark, валюты и сравнение10 карточек с АБС | Исправить pipeline, replay по version; модель не переобучать на испорченных данных |
| Изменилась инструкция или delayed outcomes | Двойная переоценка50 старых+50 новых карточек, known_at и κ по периоду | Уточнить инструкцию, пересчитать зрелые когорты; не переписать исторический label молча |
| При том же ranking упала ёмкость людей | M, минуты, backlog, переводы между очередями | Ограничить residualK, восстановить ёмкость; больший model score не лечит дефицит |

Мониторить долю сегмента, PSI/ABSTAIN, качество с CI, нормализованные жалобы, обязательную SLA/часы. PSI>0,2 — повод проверить, а не команда retrain. Регрессия: прежние редкие схемы, новые селлеры, нулевая история, missing, stale, дубли, conflict rules, bad artifact, approved version mismatch.

Выкладка: та же schema, подписанный challenger, offline →shadow→10% residual очереди при прежних квотах→расширение после контроля. Контрольная случайная ветвь сохраняется. Откат: versioned policy переключает ranking на baseline, не теряя cases/approvals; restore drill и тест replay до релиза. При нарушении mandatory/клиентского guardrail — немедленный откат, причина в audit и новый ADR.
