# ADR-001. Локальное ранжирование операций с независимым контролем

Статус: **предварительное**, принято как архитектурное направление, допуск к реальному пилоту не получен. Дата: 08.11.2026. Инициатива №1. [Контекст и постановка P1](passports.md), [варианты](selection.md).

## Контекст и жёсткие ограничения

35 тыс. сигналов и около 10 тыс. ручных проверок в месяц; нет достоверных меток схем. Банковская тайна/ПДн требуют согласования каждого потока. Нельзя отменять обязательные проверки, проводить/блокировать платёж по score, считать непроверенные операции чистыми или публиковать реальные данные. Внешние API без согласованного обработчика и условий исключены до сравнения. On-prem тоже требует цели, основания и ролевого допуска.

## Критерии и варианты

Веса после hard constraints: измеренное качество 40%, эксплуатация 25%, TCO 20%, переносимость 15%. Предварительных числовых баллов качества нет.

| Вариант | За | Против | Выбор |
|---|---|---|---|
| Только действующие правила | Доступный baseline, понятные действия | Не исследует новые закономерности, ограниченная очередь | Сохраняется при отказе и как контроль |
| Публичный LLM/API | Быстрый прототип | Нет допуска на передачу; нет нужды в генерации, слабая постановка | Исключён |
| Выделенный/cloud self-host | Управляемые мощности | Не подтверждён допуск/договор/выход, лишняя граница | Резерв после согласования |
| On-prem IsolationForest + правила | Нет зависимости от меток схем; CPU batch, переносимость | Не измеряет вероятность схемы; аномалии новых клиентов, операционные затраты | Кандидат shadow-пилота |
| Supervised схема/не схема | Прямая постановка при качественном gold | Эталон отсутствует; эскалации не заменяют его | Сейчас отклонён; вернуться после созревания gold |

## Решение по этапам

Пилот: on-prem изолированный batch; сначала сверка данных/инструкции, затем shadow без изменения текущего обслуживания. Модель не в критическом пути платежа. Экспертный контроль имеет независимый от модели отбор. Далее ограниченная остаточная очередь только при согласованной ёмкости и gates Task4.

Прод: опциональный сервис поддержки решения. Обязательная очередь вне модельного квотирования; validated recommendation → case management → сотрудник. Никакого скрытого пропуска обязательных дел. [C4, контракты, fallback](../Task3/architecture.md) — часть решения. Уровни качества ещё предстоит доказать.

## Допущения, риски и выход

| Допущение | Источник | Критично |
|---|---|---|
| Изолированные мощности/команда доступны | A1, экспертная оценка | Да, подтвердить инфраструктурой |
| Допуск и независимая инструкция достижимы | A2, гипотеза проекта | Да, без них только синтетика |
| Можно выделить контроль в пределах 10 тыс. | A3, кейс + предложение | Да, M и минуты подтвердит финмонитор |
| Инфраструктура/ставки приблизительно оценены | A4/A5, рыночный ориентир S1 | Да, чувствительность Task4 |

Риски: аномальные нормальные сегменты → сегментные метрики/ABSTAIN, смещение → случайный контроль, задержка исходов → версии и зрелые когорты, устаревшие признаки → watermark и baseline, утечка/подмена → [угрозы](../Task3/architecture.md). Внутренний score не показывается клиенту как обвинение.

Выход: portable Parquet/JSON Schema, OCI images, job manifest, model digest, CSV export кейсов и аудита в банковском контуре; не привязывать очередь к SDK вендора. При прекращении поддержки — отключить challenger, вернуть rules, воспроизвести последнюю verified версию. Резерв миграции 400 тыс. руб. — оценка Task4; экспорт без неразрешённого копирования ПДн.

Триггеры: отсутствие прав/ёмкости; провал качества/guardrails; новый сегмент/OOD; рост ресурсов вдвое; изменение тарифа/лицензии >30%; накопленный независимый gold позволяет иную постановку. Изменение прав/данных открывает ADR до нового запуска.

## История проектных решений (не история реального внедрения)

Все стадии спроектированы 08.11.2026; экспериментов и согласований ещё не было. Прежние решения сохранены.

- v0.1 / Task2 / размещение: on-prem batch, внешний API исключён до допуска. Статус предварительное, сохраняется.
- v0.2 / Task2 / модель: ~~классификатор «схема/не схема»~~ **пересмотрено**: кейс не содержит надёжного эталона. Выбран unsupervised ranking с экспертным исходом пилота и независимым контролем.
- v0.3 / Task3 / архитектура и надёжность: ~~просто top-10 000 модели~~ **пересмотрено**: обязательные дела и контроль расходуют ту же ёмкость. K_model=max(0,10 000−M−1 000), запрет автоматических действий, ABSTAIN/fallback, validation перед case management.
- v0.4 / Task4 / итог: **только ограниченный пилот**, промышленный запуск отложен. Экономия ФОТ не доказана, TCO выше текущих прямых расходов без монетизации нового эффекта. Прод возможен после измеренного выигрыша, клиентских guardrails и решения владельца риска/бюджета. [Расчёт и gates](../Task4/tco-and-pilot.md).
