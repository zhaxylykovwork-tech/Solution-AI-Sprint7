# Task2. Паспорта трёх инициатив

Раздел 0 и общий триаж — [Task1](../Task1/triage.md). Все оценки и пороги ниже проектные: фактических прогонов нет. Правовой допуск — отдельный входной gate, не предположение о разрешении.

## P1. №1 Приоритизация подозрительных операций

### 1–2. Постановка

| Поле | Решение |
|---|---|
| Без слова AI; бизнес-действие | История операций → упорядоченная очередь для сотрудника. Изменяется порядок необязательной части проверок; обязательные сигналы обслуживаются независимо |
| Объект и момент | Операция с контекстом клиента и окнами истории на момент cutoff; batch ежедневно, без синхронной задержки платежа |
| Операция × модальность | Порядок/аномалия × таблица и время. Назначение платежа пока только нормализованные детерминированные признаки, без LLM |
| Выход модели | Непрокалиброванный anomaly score, версия и диагностические признаки; не вероятность схемы и не юридическое заключение |
| Бизнес-выход | Карточка с причинами, источниками и статусом READY/ABSTAIN/FALLBACK для ручной очереди; решения HOLD/RELEASE нет в контракте |
| Где ML / где код | Источники → point-in-time признаки (код) → IsolationForest (ML) → валидация, квоты и дедупликация (код) → человек → outcomes (код) |
| Эталон | Для пилота «требует дополнительного расследования по утверждённой инструкции» — два независимых эксперта и арбитр. Escalation, outcome и formal_confirmation хранятся отдельно, последний может появиться через месяцы |
| Альтернативы | Классификатор подтверждённой схемы пока невозможен; weak-label классификатор воспроизводит эскалацию. Вопрос владельцу: нужен приоритет проверки или окончательная квалификация? Принята первая постановка |
| Не хватает | Доли схем, результатов независимого аудита, расписания обязательных проверок, прав и стоимости ошибок. [План получения сигнала](selection.md) |
| Вердикт | Гибрид; разрыв данных с планом закрытия; только условный пилот |

### 3. Качество

Бизнес-метрика: число независимо подтверждённых полезных расследований на 100 человеко-часов, своевременность обязательной очереди; отдельный долгосрочный отчёт о formal_confirmation без присвоения этого класса всем эскалациям. Baseline — действующий порядок правил на той же когорте и при равном K. Исторические 4% — ориентир загрузки, не честная precision по схемам.

Положительный исход пилота строго определён как экспертное «требует расследования». Primary: разница precision@K этого исхода с baseline и её 95% ДИ; bootstrap по клиентам/неделям, не независимым транзакциям одного клиента. Успех: нижняя граница ДИ разницы >0 и точечный относительный прирост ≥20%. Это бизнес-гипотеза для согласования, не гарантированный результат. Если мало событий/широкий ДИ — пилот не доказал пользу. Recall схем не вычисляем без репрезентативного эталона и созревших исходов.

Рабочая ёмкость K_total≤10 000/месяц при фактически доступных часах. M обязательных проверок обслуживаются первыми; K_control=1 000 случайных/стратифицированных проверок, K_model=max(0,10 000−M−1 000). Если M>9 000, сокращаем экспериментальную очередь; недостаточная ёмкость для контроля блокирует сравнительный пилот. Если M>10 000 — владелец процесса решает дефицит, ML не скрывает backlog. Дубли считаются один раз, фактические минуты важнее счётчика операций. В shadow-фазе модель вообще не меняет очередь.

Проверочная выборка: последующий месяц после обучения, без пересечения клиентов train/test для оценки новых клиентов; отдельный temporal тест знакомых клиентов. Квоты по ОКВЭД, возрасту счёта, каналу, суммам; обязательные/модельные/случайные ветви отмечены. 3 000 независимых экспертных проверок на 3 месяца (1 000/мес.) — первоначальный бюджет, не доказательство достаточной мощности. После первой 1 000 рассчитать требуемый N по наблюдаемой частоте и кластерной корреляции; не дотягивать выборку до желаемого p-value.

Отбор контроля фиксируется до просмотра исходов: 800/месяц случайно из объединения top-K rules/model, 200/месяц стратифицированно из остального разрешённого потока. Дедупликация и вероятности включения сохраняются, каждый допустимый объект имеет ненулевой шанс. Score/top-K на cutoff замораживаются до разметки; эксперты контроля не видят score/ветвь. Precision@K оценивается по контрольным пересечениям с известными inclusion probabilities, с весами и кластерным CI. Это уменьшает смещение, но не гарантирует малую дисперсию: отдельно показываем размер и эффективный N каждого пересечения. Если у одной верхушки недостаточно меток, не сравниваем сырые доли разных очередей; расширение бюджета/уменьшение K — только заранее согласованный новый этап. Для всего потока 200 наблюдений могут не обнаружить редкие схемы, поэтому recall схем и отсутствие риска не заявляются.

Метрики в рабочей точке пока **не измерены**: precision@K, CI, доля ABSTAIN, время проверки, очередь и клиентские последствия. Ложный приоритет тратит 12 минут, но не должен автоматически приостанавливать платёж; пропуск имеет неизвестный финансовый/регуляторный ущерб. Guardrails: ни одной потерянной обязательной проверки/несанкционированной блокировки, ёмкость ≤2 000 часов/месяц по кейсу, задержка обязательных проверок не выше утверждённого SLA. Жалобы и отменённые приостановки на 1 000 проверок не должны статистически ухудшаться против сопоставимого baseline; абсолютный всплеск >20% за неделю — временная остановка до разбора, не автоматическое доказательство причинности.

### 4. Готовность данных

| Проверка | Известно / разрыв / закрытие |
|---|---|
| Источник, владелец, гранулярность | Операция в АБС, клиент/счёт/контрагент, история сигналов и кейсов. Предлагаемые владельцы: АБС и руководитель финмонитора; инвентаризация lineage до пилота |
| Прод-доступность | Сумма, канал, время, доступная на cutoff история. Исключить будущий outcome, последующие блокировки и исправленные задним числом поля; as-of join и watermark |
| Объём | 20–25 млн операций/месяц — поток, объём валидных записей не установлен. Число формальных подтверждений и распределение классов неизвестны |
| Качество | До допуска: сверка числа/сумм по бизнес-дате с АБС, уникальность operationId/version 100%, заполненность критичных полей 100% либо ABSTAIN; отсутствующие назначения допустимы с индикатором |
| Разметка | Два эксперта независимо на 20% контрольного набора, арбитр разногласий; инструкция отдельно отличает транзит, обналичивание, дробление, недостаточно данных. κ≥0,7 как предварительный gate; ниже — пересмотр инструкции |
| Смещение | Исторические проверки отобраны правилами; непроверенным не ставить 0. Сохранять inclusion probability контрольной выборки; взвешенные оценки только для её целевой генеральной совокупности |
| Репрезентативность | Покрытие ОКВЭД, новых счетов, сезонов, каналов, крупных/редких операций. Отдельные отчёты, сегменты с малым N не объединять в «успех» |
| Права | Нужны цель/основание обработки, доступы, сроки хранения и допустимость связи источников; комплаенс+юрист+DPO. Пока не подтверждены — реальная обработка заблокирована |
| Итог | Разрыв с планом; получение допуска, качества и инструкции переводит в «можно начинать shadow-пилот». Промышленная классификация схем не готова |

### 5. Карточка эксперимента E1

Предполагаемая потеря — обязательные правила занимают очередь, а новая транзитная активность не попадает наверх; это гипотеза, не наблюдение. Конкуренты: плохое качество временных окон, дубли, дефицит людей, непригодная экспертная инструкция. Дешёвая проверка: сначала сверить 100 карточек и as-of признаки, затем на фиксированном будущем наборе сравнить rules и IsolationForest с одинаковым остаточным K и слепой экспертизой. Рычаг — порядок и признаки, без отмены правил. Ожидаемый эффект — ≥20% относительного прироста полезных расследований в необязательной очереди; стоимость включена в пилот Task4 (3 000 проверок ×12 мин =600 ч и 120 ч калибровки). Если нижняя граница Δprecision≤0 после заранее рассчитанного N, гипотеза не подтверждена; возврат к baseline и анализ признаков, не подбор нового порога на тесте.

## P2. №2 OCR кредитных документов

### 1–2. Постановка

Скан/фото страницы → текст, строки, координаты и confidence; оператор исправляет, затем андеррайтер видит подтверждённую оцифрованную копию. Объект — страница версии документа, по запросу загрузки, async. Операция извлечение × документ/изображение; ML — OCR, код — антивирус, поворот/контроль разрешения, типы, hash, дедупликация и контракт. Эталон — ручная транскрипция с координатами, два оператора на критичных числах, арбитр. Альтернатива: если нужен только поиск текста, требования ниже; если автоматический перенос реквизитов — нужен №18 и проверка. Вопрос: какие поля допускают автоматический перенос? В этом проекте все критичные поля утверждает человек. Гибрид, с условием доступа и эталона.

### 3. Качество

Baseline Tesseract5 rus+eng; challenger PaddleOCR с проверенными кириллическими весами. Набор 600 страниц: 300 настройка, 300 закрытый тест; не делить страницы одного документа/клиента между частями. Минимум 60 фото, 60 плохих сканов, 60 таблиц в тесте (страницы могут относиться к нескольким срезам); реальные пропорции фиксируются инвентаризацией. CER≤2% на обычном печатном тексте и ≤5% на фото — предложенные пороги; число/знак/разряд и реквизиты оценивать exact match отдельно ≥99% на тесте, а не усреднять с буквами. Показатели не измерены.

Рабочая точка — порог confidence калибруется на настройке для critical exact match; confidence разных движков несопоставим. Если порог не обеспечивает цель, страница REVIEW; критичные значения всё равно требуют утверждения. Бизнес-метрика — медианное и p95 время оператора на страницу, цель −30% при отсутствии ухудшения числа принятых ошибочных реквизитов. Первоначальная нагрузка: все 300 тестовых страниц проверены, в пилоте 100% критичных полей и ≥10% остальных страниц. Positive class неприменим к OCR, оцениваем ошибки символов/полей. Ошибка суммы может исказить кредитное решение; пропуск — возврат клиенту и задержка. Очередь, отказ по качеству и p95 end-to-end ≤2 мин на страницу при заявленной нагрузке проверяются отдельно; фактическая нагрузка пока неизвестна.

### 4. Готовность данных

Владелец кредитного документооборота передаёт разрешённые версии PDF/фото и метаданные страницы. Объём и число языков неизвестны; нет подтверждённого gold. До пилота собрать 600 страниц по типам/каналам/языкам/качеству, удалить дубли hash, проверить читаемость, права и сроки хранения. Разметка по инструкции сохраняет переносы/разряды/знак, связывает text span с bbox; 20% двойной ввод, все расхождения критичных полей арбитрирует старший оператор. Выбор только чистых сканов запрещён; фото/редкие формы отдельными срезами. Прод-признаки доступны из загружаемой страницы; исправления оператора не подмешиваются в исходный OCR тест. Статус: разрыв с планом, до правового допуска реальная обработка заблокирована.

### 5. Эксперимент E2

Гипотеза: плохие фото дают основную потерю; конкуренты — неверный язык, поворот, мелкий шрифт и таблицы. На 60 фото сравнить тот же OCR с/без deskew/качества и другой движок на одинаковом входе; измерить critical exact match и минуты исправлений. Рычаг сначала preprocessing, затем модель. Ожидаем −30% времени на фото, не «+точность вообще». Бюджет оценки: 600 страниц ×3 мин =30 ч +12 ч арбитража (экспертная оценка, не факт); stop — отсутствие выигрыша времени либо ухудшение критичных полей. Повторный скан/ручной ввод сохраняется как fallback.

## P3. №18 Извлечение финансовых показателей

### 1–2. Постановка

Подтверждённый OCR/цифровая выписка → кандидаты показателей с периодом, единицей, валютой и ссылкой на строку → андеррайтер утверждает карточку. Объект — показатель документа/периода; async после OCR, ответ по запросу пакета. Операция извлечение/связь × документ/текст/таблица. Модель выдаёт span и тип показателя; нормализация decimal и проверка связей — код; кредитного решения в выходе нет. Эталон — подтверждённый финансовым экспертом показатель, исходный span, единица, период, missing/ambiguous. Источник не гарантирует истинность отчётности; проверку подделки здесь не решаем.

В известной форме baseline — словари/табличные правила; для свободного текста кандидат XLM-R fine-tuned token classifier + resolver. Альтернативная постановка «вычислить коэффициенты из уже структурированных полей» — обычная программа. Вопрос владельцу: какие показатели и допустимые форматы? Для пилота только выручка, чистая прибыль, активы, обязательства, денежный поток за явно указанный период; всё вне списка → REVIEW. Гибрид с планом получения разметки.

### 3. Качество

Primary — exact match полного кортежа (значение, знак, валюта, единица, период, источник), а не token-F1. Положительный объект — существующий в документе корректный кортеж; отсутствующий показатель должен быть null/MISSING. Baseline — правила + ручной ввод; бизнес-метрика время переноса/проверки пакета, предложенная цель −25% именно этого этапа, а не всех 1,5 часов. Набор 400 пакетов: 200 настройка/обучение, 100 validation, 100 закрытый тест; группировка по клиенту и шаблону, отдельный тест новых форм. Отдельно ≥30 случаев тысяч/миллионов, ≥30 разных периодов, ≥20 отсутствующих полей в закрытом тесте; совпадения срезов допустимы.

Предварительные gates: exact match≥98% на покрытых полях, 100% выходов со ссылкой на существующий источник, 0 выдуманных принятых значений, корректное воздержание≥95% на missing/ambiguous. Для 98% 100 пакетов может быть недостаточно: считать CI по пакетам и полям; до подтверждения нижней границы 95% CI≥98% автоматическое принятие не разрешается. Фактические метрики неизвестны. Порог confidence подбирается только на validation; рабочая точка — все критичные поля на подтверждение человеку, max 1 вариант при конфликте источников не выбирается автоматически. Цена неверной единицы — риск неверного андеррайтинга; цена null — дополнительные минуты проверки. Guardrail: ни одного кредитного действия без утверждения; возвраты из-за ошибочного переноса не растут.

### 4. Готовность данных

Владельцы: кредитный документооборот (версии файлов) и методолог андеррайтинга (словарь/эталон). Запись = показатель+documentVersion+period+sourceSpan. Объём пакетов и меток неизвестен. Создать 400 разрешённых пакетов и gold с пропусками, конфликтами, единицами; 20% двойной экспертный ввод, арбитраж всех конфликтов. Вводятся schemaVersion, lineage OCR и точные decimal; качество — уникальность версии, наличие источника, суммы и знаки по первичному документу. Предикторы доступны из исходного документа, последующее кредитное решение исключено. Не выбирать только утверждённые кредиты/стандартные формы; новые клиенты/отклонённые заявки и плохие фото входят в разрешённую выборку. Права и ограничения связи данных — юрист/DPO/комплаенс до доступа. Статус: разрыв с планом, до правового допуска заблокирована обработка реальных файлов.

### 5. Эксперимент E3

Гипотеза: точность теряется на связывании периода и единицы, а не на распознавании цифр. Конкуренты — OCR и неверный gold. На 50 пакетов сравнить extractor на gold-тексте и на OCR, затем resolver с/без заголовков периода, сохранив модель. Рычаг — признаки/постобработка. Ожидание: снизить ошибки периода/единицы вдвое на этом срезе без роста false non-null. Бюджет: 50×15 мин=12,5 ч эксперта плюс 2 дня инженера (оценка). Stop — эффект исчезает на gold-тексте или не воспроизводится на закрытом срезе; тогда чинить OCR/разметку, не увеличивать модель. Общий initial gold 400×15 мин=100 ч +20 ч арбитража, уточняется до бюджета внедрения; TCO Task4 относится только к флагману.
